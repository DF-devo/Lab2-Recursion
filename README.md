## 1. Ханойские башни

### 1.1 Постановка задачи

Даны три стержня; на первом нанизаны N дисков разного размера, меньшие лежат на больших.
Нужно перенести всю башню на третий стержень за минимальное число ходов: за раз переносится
один диск, и нельзя класть больший диск на меньший. Головоломку придумал Эдуард Люка в 1883 г.

### 1.2 Рекурсивная идея

Чтобы перенести `n` дисков со стержня A на стержень C (через вспомогательный B):

1. перенести `n−1` дисков с A на B (рекурсивно);
2. перенести самый большой диск с A на C (1 ход);
3. перенести `n−1` дисков с B на C (рекурсивно).

База рекурсии: `n = 0` — переносить нечего.

```
function hanoi(n, from, to, aux):
    if n = 0: return
    hanoi(n − 1, from, aux, to)     // шаг 1
    вывести "диск n: from → to"     // шаг 2
    hanoi(n − 1, aux, to, from)     // шаг 3
```

### 1.3 Корректность и сложность

* Число переносов: `T(n) = 2·T(n−1) + 1`, `T(0) = 0` ⟹ **T(n) = 2ⁿ − 1** — это и есть
  минимально возможное число ходов (доказывается индукцией).
* Корректность: после шага 1 все диски кроме самого большого лежат на B (наибольший диск
  можно свободно переложить на пустой C); шаг 3 переносит башню на C уже поверх наибольшего.
* Временная сложность **O(2ⁿ)**, глубина рекурсии O(n).
* Проверка в тестах: для каждого n последовательность переносов проигрывается на стеках —
  ни разу больший диск не кладётся на меньший, и все диски оказываются на целевом стержне.

### 1.4 Реализация

`src/RecursionLab2.Core/Hanoi/HanoiSolver.cs`
* `Solve(n)` — строит полный список переносов (используется в анимации);
* `SolveCountingOnly(n)` — рекурсия без хранения переносов, для замеров на больших n;
* `FormulaMoveCount(n)` — 2ⁿ−1 для сверки.

## 2. Задача о N ферзях (дополнительно выбранный алгоритм)

### 2.1 Постановка задачи

Расставить на шахматной доске N×N N ферзей так, чтобы никакие два не били друг друга
(не стояли на одной вертикали, горизонтали или диагонали). Классическая задача
(computational puzzle, известна с 1848 г., задача №2557 проекта Эйлер — подсчёт решений).

### 2.2 Рекурсивная идея (бэктрекинг)

Ферзи расставляются по одному на строку сверху вниз: в строке `row` перебираем столбцы;
клетка безопасна, если её столбец и обе диагонали свободны (проверка за O(1) через
три булевых массива). Ставим ферзя, рекурсивно решаем задачу для `row + 1`; если ветка
зашла в тупик — **снимаем ферзя и откатываемся** (backtracking) к следующему столбцу.

База рекурсии: `row = N` — все строки заполнены, расстановка найдена.

```
function place(row):
    if row = N: solutions += 1; return
    for col in 0..N−1:
        if столбец col и диагонали (row+col), (row−col) свободны:
            занять col и диагонали; queens[row] = col
            place(row + 1)
            освободить col и диагонали      // откат
```

### 2.3 Сложность

* Дерево полного перебора — до Nᴺ вариантов; проверка «под боем» на каждом уровне
  усекает дерево до **O(N!)** листьев в худшем случае.
* Память: O(N) — глубина рекурсии плюс три массива отметок.
* Число решений известно: n=4 → 2, n=5 → 10, n=8 → **92**, n=10 → 724, n=12 → 14200,
  n=13 → 73712. Эти значения использованы как эталон в юнит-тестах.

### 2.4 Особенности реализации

`src/RecursionLab2.Core/NQueens/NQueensSolver.cs`
* Занятость столбцов и диагоналей хранится в массивах `cols`, `diag1` (индекс `row+col`),
  `diag2` (индекс `row−col+N−1`) — проверка клетки за O(1) вместо O(N).
* `SolveFirst(n)` — первое решение (останавливает рекурсию, оставляя доску заполненной);
* `CountSolutions(n)` — подсчёт всех решений (используется в замерах);
* событие `Step` публикует каждое действие (постановка/снятие/решение) — на нём построена
  пошаговая анимация бэктрекинга в GUI.

## 3. Треугольник Серпинского (дополнительно выбранный фрактал)

### 3.1 Описание фрактала

Треугольник Серпинского — самоподобный фрактал, названный в честь Вацлава Серпинского
(1915). Строится рекурсивно: треугольник делится отрезками между серединами сторон на
4 равных треугольника; **центральный выбрасывается**, к трём оставшимся применяется та же
процедура. База рекурсии — глубина 0: рисуем сам треугольник.

```
function sierpinski(A, B, C, depth):
    if depth = 0: нарисовать треугольник A, B, C; return
    AB = середина(A,B); BC = середина(B,C); CA = середина(C,A)
    sierpinski(A, AB, CA, depth − 1)   // верхний
    sierpinski(AB, B, BC, depth − 1)   // левый
    sierpinski(CA, BC, C, depth − 1)   // правый
```

### 3.2 Свойства и сложность

* На глубине d получается **3ᵈ** треугольников; каждый в 4 раза меньше исходного.
* Суммарная закрашенная площадь: `(3/4)ᵈ` от исходной → при d → ∞ площадь стремится к нулю,
  а периметр — к бесконечности (фрактальная размерность log₂3 ≈ 1.585).
* Время построения **O(3ᵈ)** — рост числа вызовов в 3 раза на каждую единицу глубины.
* Проверка в тестах: количество треугольников = 3ᵈ и суммарная площадь = (3/4)ᵈ от исходной.

### 3.3 Реализация

`src/RecursionLab2.Core/Sierpinski/SierpinskiTriangle.cs`
* `Build(...)` — строит список треугольников глубины `depth` (используется в GUI-демонстрации);
* `CountOnly(depth)` — та же рекурсия без хранения результатов, для замеров на больших глубинах.

## 4. Быстрая сортировка (дополнительно выбранный алгоритм)

### 4.1 Постановка задачи

Отсортировать массив чисел по возрастанию. Быстрая сортировка (QuickSort) — алгоритм
Чарльза Хоара (1960), один из самых используемых алгоритмов сортировки в промышленности
(основа `Array.Sort` в .NET, `std::sort` в C++).

### 4.2 Рекурсивная идея (разделяй и властвуй)

1. Выбрать **опорный элемент** (в реализации — медиана из первого, среднего и последнего
   элементов части);
2. **Разбиение** (схема Ломуто): опорный уходит в конец части; все элементы ≤ опорного
   собираются слева, остальные — справа; опорный встаёт на своё **финальное место**;
3. Рекурсивно отсортировать левую и правую части.

База рекурсии: в части 0 или 1 элемент — она уже отсортирована.

```
function quicksort(lo, hi):
    if lo >= hi: return                  // база рекурсии
    p = partition(lo, hi)                // опорный встал на место p
    quicksort(lo, p − 1)                 // левая часть: всё ≤ опорного
    quicksort(p + 1, hi)                 // правая часть: всё > опорного
```

### 4.3 Сложность

* Средний случай: **O(n·log n)** — в среднем разбиение делит часть пополам, значит
  уровней рекурсии log₂n, на каждом уровне в сумме просматривается n элементов.
* Худший случай: O(n²) — при постоянном крайнем разбиении. Выбор опорного медианой из
  трёх защищает от худшего случая на уже отсортированных и обратно отсортированных
  входах (проверяется тестом на 200 000 упорядоченных элементов).
* Память: O(log n) — сортировка выполняется **на месте**, дополнительная память —
  только глубина стека рекурсии.
* Сортировка **неустойчивая** (порядок равных элементов может меняться).

### 4.4 Реализация

`src/RecursionLab2.Core/QuickSort/QuickSorter.cs`
* Событие `Step` публикует каждое действие (выбор опорного, сравнение, обмен, фиксация
  опорного) — на нём построена анимация в GUI; без подписчика алгоритм работает на
  полной скорости (это используется в замерах).
* Счётчики `Comparisons` и `Swaps` позволяют сверить практическое число сравнений
  с теоретической оценкой n·log₂n (в тестах проверяется диапазон).

## 5. Методика замеров (как в лабораторной №1)

Для каждого размера задачи n выполняется **несколько прогонов** (3, либо 2 с флагом `--quick`),
перед которыми делается **прогревочный прогон** (компиляция JIT, прогрев кэшей).
Время измеряется классом `System.Diagnostics.Stopwatch` (высокотимальный счётчик).

Фиксируются:
* **лучшее время** — минимальный из прогонов (меньше всего искажён сторонними процессами);
* **среднее время** — используется на графиках;
* **объём работы** — теоретическая мера: переносы 2ⁿ−1 у Ханоя, число решений у ферзей,
  число треугольников 3ᵈ у Серпинского, оценка n·log₂n сравнений у быстрой сортировки.

Диапазоны замеров (время — в секундах, как на графиках и в CSV):
* Ханойские башни: n = 10…29 (0.000007 с → 3.92 с; число переносов на n=29 — более 536 млн);
* N ферзей (все решения): n = 4…15 (0.000002 с → 22.32 с; число решений на n=15 — 2 279 184);
* Быстрая сортировка: n = 2¹⁰…2²⁴ (0.0002 с → 8.44 с на 16.7 млн элементов);
* Серпинский: глубина 0…19 (0.000000 с → 5.52 с; 1 162 261 467 базовых треугольников).

Стенд: консольный проект `RecursionLab2.Bench` (`dotnet run --project src/RecursionLab2.Bench`),
результаты — таблица в консоли, `results/*.csv` и графики `results/*.png`.
Тот же стенд встроен в GUI на вкладке «Замеры времени» с возможностью сохранить CSV + PNG.

### 5.2 Выводы из графиков

* **Ханойские башни** — время удваивается при каждом +1 к n (0.033 → 0.062 → 0.125 → 0.246 … с),

  гигабайты памяти под список — сама рекурсия при этом идеальна по памяти: глубина
  стека всего d = 19 кадров.

## 6. Демонстрация (GUI)

Запуск: `dotnet run --project src/RecursionLab2.App` (Windows Forms, .NET 10).
Интерфейс выполнен в тёмной современной теме; доски и фрактал рисуются с двойной
буферизацией — без мерцания.

* **Вкладка «Ханойские башни»** — выбор числа дисков 1–12, кнопки Пуск/Пауза/Сброс,
  регулировка скорости; диски анимированно переносятся по рекурсивному решению,
  журнал ходов, счётчики «выполнено/всего» (2ⁿ−1). По завершении анимация
  останавливается сама.
* **Вкладка «Задача о N ферзях»** — пошаговая анимация бэктрекинга: ферзь ставится,
  атакованные клетки подсвечиваются, при тупике ферзь снимается (красная подсветка) —
  видно, как алгоритм откатывается. Есть пошаговый режим «Шаг», поиск первого решения
  или всех решений, счётчики попыток/откатов/решений. **Все найденные решения
  накапливаются** — после завершения поиск ставится на паузу автоматически, и решения
  пролистываются кнопками «◀ Пред. решение / След. решение ▶».
* **Вкладка «Быстрая сортировка»** — массив рисуется столбиками: опорный элемент
  подсвечен зелёным, текущее сравнение — оранжевым; видно разбиение вокруг опорного
  и рекурсивный спуск в обе части. Регулировка скорости, пауза, генерация нового
  массива, счётчики сравнений и обменов; по завершении анимация останавливается сама.
* **Вкладка «Треугольник Серпинского»** — ползунок глубины 0–9 (число треугольников 3ᵈ
  и время построения показываются сразу), автоматическая анимация роста глубины,
  экспорт в PNG.
* **Вкладка «Замеры времени»** — запуск любой серии замеров прямо из GUI, таблица
  результатов (время в секундах), график с логарифмической/линейной шкалой,
  сохранение CSV + PNG.
